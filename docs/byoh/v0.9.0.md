# Bring Your Own Harness in v0.9.0

## Reproduce the current behavior

Use a disposable workspace with these two files. The fixture contains no Dashboard configuration, Harness SDD manifest or feature registry.

**CLAUDE.md**

```markdown
# Team instructions
Review contributions to this workspace.
```

**.claude/agents/reviewer.md**

```markdown
---
name: reviewer
description: Review contributions to the native workspace.
---
Read changed files before preparing a review.
```

Launch the Extension Development Host with this folder as its workspace. Run **Harness: Open Dashboard**, inspect the framework badge and the reviewer node, then open Advisory and Optimizer. Use **Harness Dashboard: Re-scan Agentic Architecture** for a fresh profile and **Harness: Optimize Components** for a fresh report. For TypeScript source breakpoints use the development bundle with sourcemaps (`npm run watch`).

At commit `d894313`, a macOS Extension Host probe called the production parser, detector and optimizer on this fixture. It inspected the data returned by the engines. The detector ran without the optional whiteboard graph context.

| Inspect | Observed at 0.8.2 | Expected in 0.9.0 |
|---|---|---|
| Graph | Detected Claude Code. `claude-code::root` points to `CLAUDE.md` and `claude-code::reviewer` points to the native agent file. | Both panels retain that attribution and explain which operations are available. |
| Advisory | Maturity L1. Returned `cli-without-impl`, `adopt-sdd`, `add-claude-md` and `use-skill-files`. | Existing project instructions count as evidence. SDD adoption is an explicit user choice. Findings show the provider or workspace evidence that triggered them. |
| Optimizer | Returned `OPT-S02`, `OPT-S05` and `OPT-O02` for the reviewer. S02 proposes setting its name to the parent directory, `agents`. | Native naming and section requirements apply only when declared by the source owner. Shared checks still run where their inputs exist. Unevaluated dimensions are visible. |

Useful breakpoint sequence: `AdapterRegistry.parse` → `AgenticDetector.scan` → `generate` in advisoryEngine.ts. Inspect the claimed files, retained signals and suggestions. For Optimizer, follow `loadComponents` → `scan` in optimizerEngine.ts → `optS02.evaluate`. Inspect the source path, native name, rule applicability and proposed edit. The host dispatchers are AdvisoryCoordinator.handle and OptimizerCoordinator.handle.

## Proposed release acceptance

1. Exercise the shared [ownership and capability contract](../../specs/byoh-source-capabilities/requirements.md) with a built-in harness, a team Markdown profile outside framework directories, and a registered companion adapter. Repeat after a rescan and provider disposal.
2. Exercise [Advisory](../../specs/byoh-advisory/requirements.md) and [Optimizer](../../specs/byoh-optimizer/requirements.md) in SDD-only, foreign-only, custom, mixed and unrecognized workspaces. Compare actual panel output to the native files. A mixed project must retain distinct owners even when two agents have the same name.
3. Through normal commands and webview actions, verify an authorized edit with confirmation and rejection of stale, read-only, ambiguous or unsupported targets. Compare file contents and script sentinels before and after discovery. Exercise all existing mutating surfaces listed in the [migration inventory](feature-compatibility-matrix.md), including the graph editor, lifecycle commands and runners.
4. Record the seven advertised adapters’ [real-workspace smoke results](adapter-capabilities.md). Report the built-in adapter, public API and profile coverage actually verified. Run build, unit, Extension Host, packaging and project checks on the candidate. At release preparation, update the extension version and its pinned assertion together and verify the VSIX is below 400,000 bytes.

The current release is 0.8.2. This guide describes the acceptance target for 0.9.0. The maintainer approved FEAT-041, FEAT-042 and FEAT-043 at spec revision `d7b4c7e`. Implementation starts with FEAT-041 once the current FEAT-040 review frees the implementation slot.
